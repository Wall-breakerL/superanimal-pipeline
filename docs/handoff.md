# 当前阶段交付与下一步

## 本阶段范围

将实际使用的单鼠 SuperAnimal 推理与历史清洗流程提取为独立 Python 仓库；提供配置、manifest、命令行、步骤进度、安全续跑、10/27 点 H5、叠加视频和可追溯 QC。不依赖 AutoCBE 的主流程，不调用 LLM，不进行 MoSeq 或行为统计。

保留历史清洗核心原文，新代码包裹输入检查、流程组织和导出。科学方法的已知局限见 `methods.md`，实际运行证据及未验收项目见 `verification.md`。

## 使用顺序

1. 安装固定版本依赖，执行 `sap doctor`。
2. 准备单鼠视频，或者在 manifest 明确两个箱体各自的裁剪区域。
3. 确定使用固定权重、上游 zero-shot，还是已有原始 JSON/H5。适配训练只能由使用者显式运行 `sap adapt`，不是普通批处理的隐含步骤。
4. 新建配置及独立输出目录，运行 `sap check`。
5. 在 tmux 运行 `sap run`，结束后执行 `sap verify`；必须检查叠加视频和 QC，不能只看退出码。
6. 下游使用 `data/<trial>/02_cleaned.h5` 和 `01_original.mp4`；导出 10 点时仍保留完整 27 点副本。

## 托管状态与后续边界

- **GitHub 托管**：代码已建立私有仓库 `Wall-breakerL/superanimal-pipeline`；转公开、选择开源许可证和授予他人访问权限仍需仓库所有者决定。实验视频和模型权重不上传。
- **整机迁移**：本次部署独立工具副本用于验收，不是搬迁全部实验。旧服务器代码、环境、原始数据、模型、结果和日志的完整迁移需要单独盘点、复制、校验。
- **GPU 验收**：当前 RTX 4090 已通过 200 帧新推理、清洗、导出和续跑补验，见 `gpu-validation-20260910.md`。以后迁移到新服务器仍须先做短视频验证；不由此自动启动全部 trial。
- **科学验收**：没有人工标注真值，不声称清洗提高了定位精度，也不对实验造模成败作结论。

## 发布包边界

Git 中仅包含代码、配置示例、测试和文档。真实数据、私有配置、SSH/API 凭据、权重、环境与测试过程文件均不进入发布包。打包后仍需由作者检查代码来源和公开授权；选择依赖的许可证不等于选择本项目许可证。
